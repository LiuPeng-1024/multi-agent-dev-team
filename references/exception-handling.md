# 异常处理与任务画像驱动限制 (Exception Handling & Task-Profile-Driven Limits)

> **防失控的应用层补充**:`guardrails.md` 管**流程控制**(循环/预算/升级阶梯,一律按"撞墙→叫人");本文件管**按场景的失败 handler**(同一触发,不同任务画像走不同恢复)。两者互补,不重叠。
>
> 本文件解决审计确认的两类缺口:① 流程限制是平铺常量(5min/5轮一刀切)、失败 handler 单一(超时→永远降级主会话);② 6 类必要边界完全缺失(副作用门禁/工具失败分流/非超时崩溃/context溢出/幂等重试/并发上限/熔断)。

## 为什么需要本文件(第一性)

`guardrails.md` 的默认值(5轮/5min/50步)是**项目级**平铺常量,标注"可按项目调"。但一个项目里同时有"读一个文件取值"和"生成200行+跑测试"和"跑迁移脚本部署"的子代理,都吃同一个 5min——这不合理。更要命的是**失败 handler 也单一**:超时→永远"降级主会话",不管这任务是 trivial 查证(为小事破隔离不值)还是副作用型部署(自动重试=可能双写)。

可靠交付需要:**限制和 handler 都是 `f(任务画像)`,不是常量**;且**同一个触发,不同画像走不同恢复**。本文件定义这个函数。

> ⚠️ **诚实声明**:画像分类由编排者(LLM)判断,**降低而非消除** P4 误判风险。缓解见下"默认从严"+"执行时硬停",但只有真实项目跑才能暴露误判率。文档改动无法单测——这是已知验证盲区(见文末"残留风险")。

## 核心概念:Task Profile(任务画像)

### 5 维分类(每个任务在每维打标)

| 维度 | 取值 |
|------|------|
| 认知重量 | 只读查证 / 生成+验证 / 多模块集成 |
| 爆炸半径 | 低(可替换·文本) / 中(核心逻辑) / 高(鉴权·资金·不可逆) |
| 可逆性 | 可重生成(幂等) / 副作用型 |
| 确定性 | 纯计算 / IO·网络(flaky) |
| 新颖度 | 常规 / 探索 R&D |

### 5 个具名画像(常见组合)

| 画像 | 典型组合 |
|------|---------|
| **P1 事实查证** | 只读查证 + 可重生成 + 低爆炸半径 |
| **P2 独立生成** | 生成+验证 + 可重生成 + 纯计算或可控 IO |
| **P3 集成型** | 多模块集成 + 可重生成(编排者直接做,不派子代理) |
| **P4 副作用型** | 可逆性=副作用(★危险画像) |
| **P5 探索 R&D** | 新颖度=探索,无已知解 |

### 严者胜规则(安全关键)

画像不总是正交(一个任务可能"集成型 + 副作用型",如串接 deploy 步骤)。**precedence:P4 > P3 > P5/P2/P1**(在安全相关 handler 上)。任一维落"副作用"→套 P4 handler,不论其它维;任一维"高爆炸半径"→收紧(降循环上限 + 强制双重确认)。防止危险场景被其它维度稀释。

### 默认从严(防误判,缓解 A)

分类存疑时套**更严**画像:可逆性存疑→按 P4;爆炸半径存疑→按高;认知重量存疑→按更重的一档。宁可过严(多叫一次人)不可过松(P4 被当 P2 → 双写)。

### 副作用精确定义 ★(缓解 D,被编排者/开发者共用)

> **副作用 = 改不可幂等重做的共享/外部态**。例:deploy/发版、外部 API 真实效果(发邮件/发消息/扣款)、共享 DB/共享文件的不可逆改、CI 触发、通知推送。
>
> **显式排除**(=可重生成,属 P2):工作区内本地文件读写(可 git reset/重生成)、本地测试的副作用(测试 DB/临时态)、内存态 mock。这些重做无代价,可自由重试。

判定锚点一句话:**"这操作重做一遍,会不会产生两次真实外部效果?"** 会→副作用→P4;不会→可重生成→P2。

### 4 问决策树(操作捷径,缓解 E)

编排者实际执行用 4 问,不背 5 维矩阵:

```
Q1: 改不可幂等重做的共享/外部态?  → 是 → P4
Q2: 只读查证(不改任何代码)?      → 是 → P1
Q3: 需看 ≥2 个模块的实际接口才能写? → 是 → P3
Q4: 探索 R&D,无已知解?           → 是 → P5
   否 → P2(最常见,基线)
```

5 维是理论;4 问是操作。**副作用维是唯一强制必填**(Q1 必答),其它维可省。

## 画像 → (限制 + handler) 总表 ★唯一真相

数值与 handler 都随画像变。差异关键在 **handler 列**(同一触发不同恢复):

> ⚠️ **2026-07 修订(基于真实使用反馈)**:超时数值全面放宽 + 新增"进展优先于墙钟"原则。原 5-10min 墙钟对 P2 太激进——子代理在等 API 响应(DeepSeek ~60s/次)、跑测试、处理难度差异大的任务时,墙钟长 ≠ 死循环。按墙钟一刀切 → 几乎所有子代理被杀 → 降级主会话 → 主模型包揽一切。修正:超时数值按画像放宽 + **有进展就不算超时**(墙钟基准只是"该看进展了",不是"该杀了")。

| 画像 | 超时(墙钟基准) | 内层循环 | 升级深度 | 超时 handler | 崩溃 handler | 输出不可解析 handler |
|------|------|---------|---------|-------------|-------------|---------------------|
| P1 事实查证 | 60s | 1-2 轮 | 1 级 | 放弃+问人(**不**降级主会话) | 同 | 重发 1 次→问人 |
| P2 独立生成 | **15-30min**（生成+验证+等API是常态） | 5 轮 | 全阶梯 | **先查进展**:有进展→续派;无进展→升级阶梯→走完才降级主会话 | 重派 | 重发结论段 |
| P3 集成型 | **30-60min**（多模块串接本就重,编排者自己做） | 100 步 | 拆分/叫人 | N/A(编排者做) | N/A | N/A |
| P4 副作用型 | **按操作实际耗时调**（快副作用 5min / 慢副作用如大DB迁移可到 30min+），handler 不变 | 2-3 轮 | 任何异常→停+checkpoint+叫人 | **绝不自动重试** | 停+checkpoint+问人 | 停+问人(不知执行到哪) |
| P5 探索 R&D | 按预算不按时间 | 宽 | 按预算不按轮 | 容忍死胡同 | 容忍 | 容忍 |

> `guardrails.md` 的平铺默认现降级为 **P2/P3 基线**;其它画像按本表覆盖。
>
> ⚠️ **"进展优先于墙钟"原则**:墙钟达到基准时,编排者**第一动作是查进展,不是 kill 子代理**。有进展(部分代码产出/测试部分通过/有新工具输出)→ 续派;无进展(连续 2 轮无净进展)→ 走升级阶梯。只有"无进展+升级阶梯走完"才降级主会话。这防止"等 API/跑测试的合理耗时"被误判为死循环。
>
> ⚠️ **"循环上限"与"异常即停"不矛盾**:循环上限(如 P4 的 2-3 轮)是**正常进展的耗尽上限**——任务正常推进但迟迟不收敛,到上限走升级。而"任何异常→停+叫人"是**失败中断**——出错/超时/崩溃不等满轮,立即触发 handler。两件事:一个是"没收敛",一个是"出错了"。P4 出错绝不熬到满轮。
>
> ⚠️ **P4 超时数值可调,handler 不变**:P4 默认超时"快副作用 5min"针对发通知/小API调用。**已知慢副作用**(大DB迁移/慢deploy/批量外部调用)按操作实际耗时调高超时——但**handler 不变**(任何异常/超时仍=停+checkpoint+叫人,不重试)。调的是"何时怀疑无进展",不是"失败后可重试"。

## 6+1 个缺失 handler(各自:触发 / 检测 / 场景化恢复 / 何时叫人)

### 1. 副作用操作门禁(最重要)

- **触发**:任务画像落 P4(任一维副作用,含严者胜触发)
- **检测**:双层——dispatch-time 编排者 4 问分类 + execution-time 开发者遇副作用**硬停**(补 dispatch 误判)
- **pre-flight**:建**幂等令牌**(唯一操作 ID)+ **checkpoint**(git commit / 状态快照 id,记入区块 4.1 检查点列)
- **in-flight 恢复**:**任何**异常/超时/崩溃 → 立即停(不重试)→ 记 checkpoint(执行到哪)→ 问人
- **post**:测试工程师验证副作用态(是否已执行/执行到哪/是否半残)
- **何时叫人**:**任何异常即叫人**。副作用型无安全自动恢复路径
- **铁律**:**绝不自动重试**——子代理超时你不知道它写没写进去,重试=可能双写/双发
- **超时数值可调,handler 不变**:P4 默认超时"快副作用 5min"针对快副作用(发通知/小API调用)。**已知慢副作用**(大DB迁移/慢deploy/批量外部调用)按操作实际耗时调高超时(可到 30min+)——但**handler 不变**(任何异常/超时仍=停+checkpoint+叫人,不重试)。调的是"何时怀疑无进展",不是"失败后可重试"
- **进展优先于墙钟**(2026-07 修订):即便 P4,墙钟达基准时也先查 checkpoint/执行日志看进展——有进展(操作已部分执行/日志在更新)→ 不立即叫人,继续观察到操作完成或真无进展;无进展(日志停滞/操作卡死)→ 立即停+checkpoint+叫人。这条与"绝不自动重试"不矛盾:不重试的是"失败后重来",观察的是"在途操作是否还在推进"

### 2. 工具调用失败分流(瞬时 vs 永久)

- **触发**:Bash/Write/Read/外部 API 返回错误
- **检测**:退出码≠0 / 异常 / 超时
- **分流恢复**:
  - **瞬时错**(超时 / 网络 5xx / 资源暂缺)→ 退避重试(指数退避,上限 N=3)
  - **永久错**(4xx / 鉴权失败 / 文件不存在 / 参数错)→ **不重试**,立即升级
- **何时叫人**:永久错且角色无法修(如缺凭证)→ 叫人;瞬时错重试 N 次仍败 → 叫人

### 3. 子代理崩溃(非超时)

- **触发**:子代理立即错误返回 / 被杀 / 输出完全缺失(**非超时**)
- **检测**:返回错误码或空/异常输出,且未达超时阈值
- **恢复**:与超时分离——按**永久错**处理(除非换 prompt 重派一次);记运行时记录(区块 2 活跃上下文或 4.1 检查点列)
- **何时叫人**:换 prompt 重派一次仍崩 → 叫人(任务不可行 / 子代理类型不符)

### 4. context 溢出

- **触发**:子代理/角色 context 接近上限
- **检测**:预估输入+历史将超模型窗口,或工具报 context length error
- **恢复**:`headroom` 压缩/摘要历史;或**分片**任务(拆成更小子代理);或升级主会话(若主会话有余量)
- **何时叫人**:压缩+分片后仍装不下 → 叫人(任务太大需人重分解)
- **铁律**:**绝不静默截断**——截断=丢上下文=幻觉温床(违反 anti-hallucination 约束 1 工具锚定)

### 5. 幂等重试约束

- **触发**:升级阶梯 / 工具失败分流决定"重试"
- **检测**:重试前判任务画像
- **恢复**:重试仅 **P1/P2/P3** 安全(可重生成/幂等);**P4 无幂等令牌 → 禁重试**,走副作用门禁
- **何时叫人**:P4 需重试但无幂等令牌 → 叫人(人决定是否安全重做)

### 6. 并发度上限

- **触发**:编排者派并行子代理
- **检测**:当前在飞子代理数
- **恢复**:上限 N(可配,默认 4);超限 → 排队,不派
- **何时叫人**:N 持续打满且任务堆积 → 叫人(分解过细 / 资源不足)

### 7. 熔断(circuit breaker)

- **触发**:某子代理/某角色连续失败
- **检测**:连续失败计数 ≥ 阈值(默认 3)
- **恢复**:停止向该子代理/角色派发,走升级阶梯(换角色/重新分解);冷却后可再试一次
- **何时叫人**:冷却后仍失败 → 叫人(该路径系统性不可行)

## 残留风险(诚实)

1. **分类是 LLM 判断,P4 误判仍可能**。默认从严 + 执行时硬停降低概率不归零。误判方向:把 P4 当 P2 → 自动重试 → 双写。缓解已尽(双层判定+严者胜),残余靠真实项目跑暴露。
2. **文档改动无法单测**。"通读查一致性"恰是框架反对的"看代码觉得对"。本协议的验证只能靠纸面试跑(取真实 deploy 任务走 4 问→P4→门禁→失败 handler)+ 真实项目跑。
3. **画像增加编排者认知负担**。用 4 问决策树(非 5 维矩阵)+ 内容集中在本文件(其它文件指针化)降低;但编排者仍是瓶颈候选(见 `isolation-protocol.md` 代价声明)。

> **核心原则不变**:系统永远要有出路,最高出路是"停下来叫人"。本文件增加的是"不必停就能自愈"的路径(可恢复错误有 handler),但 P4 永远是"停+叫人"——副作用型没有安全自愈。
