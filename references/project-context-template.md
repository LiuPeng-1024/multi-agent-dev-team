# 事实来源文档模板 (Single Source of Truth)

> 这是多智能体团队的唯一可信基准。所有智能体动手前先读对应区块,产出后更新对应区块。
> **不更新文档的产出,等于未交付。**

把本文件复制到项目根目录,命名为 `PROJECT_CONTEXT.md`,按项目情况填充。

### 0.0 文档版本化(持续交付用,改错可回退)
> 每次变更文档,**版本号+1**(v0.1→v0.2),并在区块10变更历史记"v0.x 改了什么"。重大变更(改需求/架构)存档一份 `PROJECT_CONTEXT.v0.x.md`(上次稳定版),改坏了能回退到上次稳定的需求规约。轻微变更(改状态/进度)只更版本号+变更历史,不必存档。

## 8. 验证与质量状态 ★全自动项目的命脉
> 这是"代码到底对不对"的唯一仲裁。
### 8.1 测试现状:覆盖率[...] / 关键测试[...] / 已知失败[...]
### 8.2 质量门禁(什么算"可合并"):全量测试通过 / 无类型错误 / 覆盖率未降 / 审查者放行
### 8.3 可执行验证规则 (execute-verify) ★持续交付命脉
> 每条规则=一个可被 `guard-check --execute` 独立执行的验证。结果由**真实退出码/文件存在性**决定,非模型声称。
> **默认模式(不传 --execute)无法验证**,只 warn"未独立执行";只有 `--execute` 是非伪造 oracle。
> ★标=必绿(P0验收对应),任一红则 FAIL 阻断交付。测试工程师维护命令类规则;编排者维护 exists 类。

| 规则ID | 验证什么(claim类型) | 命令/路径 | 期望信号 | 维护者 |
|--------|---------------------|----------|----------|--------|
| V-REG★ | 回归全绿 | node tests/x.js | pass | 测试工程师 |
| V-COV★ | 覆盖率达标(工具配threshold非0退出) | npm run coverage | pass | 测试工程师 |
| V-TSC | 无类型错误 | tsc --noEmit | pass | 测试工程师 |
| V-LINT | 无lint错误 | npm run lint | pass | 测试工程师 |
| V-FILES★ | 关键工件落盘 | game.js, index.html | exists | 编排者 |
| V-REPRO-H3 | 缺陷H3未修(该复现仍失败) | node repro/h3.js | fail | 审查者 |
| V-UI-STRUCT★ | UI 结构/交互(断言来源=INTERACTION_SPEC.md §6 回归断言;按技术栈 Playwright/移动端 UI 自动化/截图 diff) | npx playwright test | pass | 测试工程师 |
| V-VISREG | 视觉回归(截图diff,首跑建基线) | node tests/visreg.js | pass | 测试工程师 |
| V-A11Y | 无障碍(axe) | npx @axe-core/cli http://localhost:3000 | pass | 测试工程师 |
| V-DESIGNSYS | 设计系统grounding(重跑search.py比对) | node tests/designsys.js | contains:<主色名> | 测试工程师 |

**期望信号(只4种)**:`pass`=退出码0 / `fail`=退出码≠0 / `contains:<文本>`=stdout含该文本 / `exists`=路径列表全存在(走os.path,**不执行命令**,天然安全)。
**不在表里的claim类型**(UI/视觉验收、设计/可维护性判断、隔离执行、性能阈值)=**判断类,无oracle**,靠多视角(红队/交叉核对)+人gate5,不可当oracle级可信。

## 14. 未知/盲区日志 ★落地后深审(见 `anti-hallucination.md` 补注3)
> 记"诚实承认不确定的"——和区块11(幻觉日志)不同:11 记被抓到的谎(gate,规律标签回流必查),14 记主动坦白的盲区(**不 gate**,落地后深审消费)。尤其 04/03 填。知识管理者维护。

| 未知ID | 角色 | 任务 | 不确定项 | 类型 | 当前处理 | 深审标记 |
|--------|------|------|---------|------|---------|---------|
| U-001 | [开发者] | [T-012] | [如"并发取消是否真清理了监听"] | [假设/推理当验证/没查当没事/盲区] | [已ship标风险/已降级/已叫人] | [待审/已审/关闭] |

> **类型说明**:**假设**(未验证就依赖)/ **推理当验证**(推了没实测)/ **没查当没事**(没读没跑说"应该ok")/ **盲区**(边界·副作用·并发·性能没把握)。
> **升级路径**:条目若被证明"明知不确定却声称完成" → 移入区块11(隐瞒≠诚实坦白)。
> **消费**:落地后深审逐条——能补实测→派04/05;未验证假设→人/实验确认;架构盲区→03重评;不需深究→关闭。类比区块6(技术债):6=结构债 03 驱动还,14=知识债 落地后深审还。
